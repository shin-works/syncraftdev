## 1. コンセプト

**現行コピーをそのまま活かし、TimeSenseのオフセットUIとキャラクターで、子どもがワクワクするページをつくる。**

### 必須条件: 現行コピーを変更しない

検索流入を意図して設計された文言として、以下を固定する。前案のメインコピー・サブコピー差し替えは撤回する。

| 要素 | 維持する文言 |
| --- | --- |
| H1内の種別表記 | 知育時計アプリ |
| メインコピー | 子どもが"時間を感じて"動く |
| サブコピー1行目 | 知育時計 × 声かけタイマーで |
| サブコピー2行目 | 子どもの「時間感覚」と「自立」を育てる |

語句・記号・語順は現行HTMLを基準に維持する。変更対象は書体、文字サイズ、行間、表示上の改行、配色、余白、周囲の構図。主要コピーは初期HTMLの読めるテキストとして残し、「知育時計アプリ」とメインコピーのH1内の関係も維持する。短い新コピーへの置換、画像化、装飾の背面への隠蔽は行わない。

他の既存見出し・本文も維持を基本とする。文章の修正が必要な箇所は、リデザインに混ぜて書き換えず、別の原稿差分として提示する。title、meta description、canonical、hreflang、既存URLも維持する。

子どもがキャラクターに興味を持ち、保護者が使い方と価値を理解できる体験をつくる。TimeSenseの時計・声・キャラクターを大きく見せ、親子で眺めたくなる、明るい絵本のような世界観にする。

見た目の主役は子ども向けの楽しさ。情報設計は、保護者が機能・無料版と有料版・利用方法を判断しやすい順番にする。

## 2. 現状からわかったこと

- 現行LPの第一画面は、ピンクのグラデーションにロゴ・見出し・ストアバッジを中央配置している。実際の時計画面やキャラクターの個性を、ここでもっと伝えられる。
- LPの定義色はピンク `#FF6B8A`、シアン `#3ACDDF`、黄色 `#FFCF56`。アプリ本体の現在の配色とは差がある。
- アプリ本体には、水色・濃紺のデフォルトに加え、Sunny / Forest / Lagoon / Terracotta / Nightのテーマがある。今回は「プロジェクトの配色を踏襲」を、アプリ本体の色を主軸にする方針として解釈する。
- ユーザーが重視するアプリと参考ページの共通点はオフセット表現。特にLagoonの、白い面・水色の背景・右下へずらした色面・押し込めるボタンの関係をLPの基本にする。各色への展開も、背景と影の組み合わせで揃える。
- 同程度の大きさのカード、グラデーション、ぼかし影、常時動く装飾が繰り返され、情報の強弱がつきにくい。書体変更だけでなく、構図と見せる順序を変える必要がある。
- Luma / Pico / Milo / Totoの画像と日本語の試聴音声が既にある。ここを体験の中心にする。
- アプリ側にもキャラクターの全身・表情・ポーズ差分がある。大きく使う素材は、実装前に解像度と透過状態を確認する。
- FAQにはルーティン・プロフィール・スタンプカードの説明がある一方、上部は時計と声かけ中心。公開版の仕様を確認して、既存機能を補足できる余地がある。

## 3. 参考サイトとトレンドの取り入れ方

[UGOKKO](https://ugokko.jp/)は、画面幅を使う大きな文字、主役として配置したキャラクター、人物やイラストの重なり、色面の切り替えで、楽しさを表現している。TimeSenseでは、時計の円形と既存キャラクターを使ってこの構成上の考え方を取り入れる。

| 取り入れる要素 | TimeSenseへの展開 |
| --- | --- |
| 大きく印象的なタイポグラフィ | 現行コピー全文をZen Maru Gothicで組み、幅に応じて改行・サイズを調整 |
| 面をずらして重ねるオフセット | アプリの時計・カード・ボタンにある、輪郭の明確な色面と押し込み表現を展開 |
| キャラクターが主役の構図 | 時計画面の周りにLumaたちを大小差をつけて配置 |
| 全幅の色面と自由な配置 | アプリの水色・黄色・コーラルでセクションの雰囲気を変える |
| スクロールした先への期待 | 円弧、点線、キャラクターの視線で次の内容へ導く |
| 触ると反応する楽しさ | 音声ボタンとキャラクターの表情・吹き出しを連動 |

2026年の傾向として、ブランド全体の色体系を活用する表現、文字自体の存在感、内容の要点を早い段階で伝える構成が挙げられている。[Webflowの2026年デザイントレンド](https://webflow.com/blog/web-design-trends-2026)を参考に、TimeSenseに合う要素として採用する。採用案はデザイン上の判断であり、成果を保証するものではない。

参考サイトの画像や固有のキャラクターは流用しない。TimeSenseの既存資産で一貫した世界観をつくる。

## 4. デザインの基本仕様

### 配色

| 用途 | 色 | 出典・扱い |
| --- | --- | --- |
| 基本背景・ヒーローの第一候補 | `#4AC4E4` | Lagoonの背景色 |
| 白い面の背面・オフセット | `#42A5C2` | Lagoonの影色 |
| 見出し・本文 | `#17345B` | Lagoonのブランド文字色 |
| 主要な独自ボタン | `#6367B0` | Lagoonの主要ボタン色 |
| 紫ボタンのオフセット | `#4F5298` | Lagoonの主要ボタンの影色 |
| 穏やかな補助背景 | `#D2EDF7` | アプリのデフォルト背景 |
| 補助の濃紺 | `#0D335A` | アプリのデフォルトの文字色 |
| デフォルト背景のオフセット | `#91C8DB` | アプリのデフォルトの影色 |
| 明るいアクセント | `#F9E760` | Sunnyテーマ |
| 強調・吹き出し | `#E96B68` | Terracottaテーマ |
| 活用シーンの補助色 | `#94B39C` | Forestテーマ |
| 夜の画面紹介 | `#2E3A59` | Nightテーマ |
| 読むための背景 | `#FFFFFF` | 白 |

Lagoonを小さな差し色に限定せず、ページの主要なデザイン基準にする。鮮やかな水色の背景、白い前面、青緑の背面、紫の操作ボタンを組み合わせる。本文は濃紺で読みやすくする。黄色・コーラル・Forestはセクション単位で展開し、背景と影の関係を保つ。全色を同じ面積で並べない。既存LPのピンクは、素材の中に残る色として調和させる。

濃紺のボタンには白文字、黄色・水色の面には濃紺文字を基本とする。コーラル上の小さな白文字などは、実際のコントラストを確認してから採用する。

### フォント

日本語は **Zen Maru Gothic** を採用する。本文400、見出し700、ヒーロー900を基本とし、必要なウェイトだけ読み込む。公式配布では300 / 400 / 500 / 700 / 900を確認できる。[Google Fontsの公式メタデータ](https://github.com/google/fonts/blob/main/ofl/zenmarugothic/METADATA.pb)

- ヒーロー見出し: PC 64〜88px、スマホ36〜44pxを出発点に実文字で調整。
- セクション見出し: PC 36〜48px、スマホ28〜32px。
- 本文: 16〜18px、行間1.8前後。長いFAQは行長を抑える。
- 見出しの強調は大きさ・太さ・部分的な色面で表現。本文の読みやすさを優先する。
- 日本語の改行は意味のまとまりで制御し、端末幅に追従させる。
- フォントは表示を妨げない読み込みにする。韓国語・中国語は各言語に適したフォールバックを別途指定する。

### 形とレイアウト

- 時計を連想する円・半円・扇形・目盛りを、TimeSense固有のモチーフとして使う。
- セクションのつなぎは、大きな円弧と波形を限定的に使用する。
- 大きな時計画面、切り抜きキャラクター、短い吹き出しを重ね、画面の中に大小のリズムをつくる。
- 通常カードの角丸は24〜32px程度。前面と同じ輪郭を持つ背面を右下へずらし、はっきりとした厚みをつくる。
- PCの本文コンテナは最大約1200px。色面と装飾は画面幅を使う。
- セクション余白はPC 96〜144px、スマホ56〜80pxを基準に、内容量で調整する。

### オフセットをページ共通の表現にする

アプリでは、時計の背面円を直径の3.5%だけ右下へずらしている。設定カードにはぼかし0・右下8pxの影があり、共通ボタンは前面が背面へ移動する押し込み動作を持つ。この構造をWebの見せ方に引き継ぐ。

| 対象 | LPでの扱い |
| --- | --- |
| 大きな時計・ヒーローの面 | 輪郭がくっきりした背面を右下に配置。時計の実画面に既に影がある場合は二重に足さない |
| 特徴・キャラクターのカード | 右下6〜10pxを出発点に、白い前面とテーマ色の背面を重ねる |
| 試聴などの独自ボタン | 右下4〜6pxの背面。押すと前面が背面側へ沈み、離すと戻る。アプリの約140msの動きを基準に調整 |
| FAQ | 白い面と小さなオフセットで統一。長文の可読性を保つ |
| ストアバッジ | 公式画像の形は維持。必要なら周囲の配置面にオフセットを適用 |

影は不透明な色面とし、ぼかし0を基本にする。ページ内の方向は右下で統一し、スマホは余白に合わせてずれ幅を縮める。静的なカードには押せそうな動きを付けず、操作できる要素に押し込みを使う。文字そのものへの強いずらし影は、主要コピーの読みやすさを優先して控える。

色の対応はアプリを基準にする: Lagoon `#4AC4E4 / #42A5C2`、Sunny `#F9E760 / #D9C545`、Forest `#94B39C / #56A972`、Terracotta `#E96B68 / #C75357`。前者は背景、後者は基本の影。ボタンなど個別の影指定がある場合はそれに従う。Nightはアプリの現状では影が透明なので、実画面の表現はそのまま使う。

確認元: [時計の背面構造](/Users/user/dev/Timesense/lib/features/clock/analog_clock.dart)、[押し込みの共通部品](/Users/user/dev/Timesense/lib/core/widgets/pressable_offset_surface.dart)、[設定カードの影](/Users/user/dev/Timesense/lib/features/settings/views/settings_dialog.dart)。数値はアプリ実装の参照値とLP用の提案値を区別し、プレビューで調整する。

## 5. ページ構成と既存要素の引き継ぎ

ページ全体の流れ: **楽しそう → 使い方がわかる → 声を聞く → 日常で使う場面が浮かぶ → 安心してダウンロード。**

| 順序 | セクション | 活かす既存要素 | 新しい見せ方 |
| --- | --- | --- | --- |
| 0 | ヘッダー | ロゴ・言語切り替え | 特徴 / キャラクター / FAQ / ダウンロードへの短いナビ。スマホは簡潔なメニュー |
| 1 | ヒーロー | 現行H1・サブコピー全文・ロゴ・両ストアへのリンク | Lagoonを基準に、現行コピー・時計・キャラクターを大きく配置。背面の色面で厚みを出す |
| 2 | TimeSenseとは・共感 | `about`と`problem`の見出し・本文 | 現行文を使った吹き出しと余白で、共感から使い方へつなぐ |
| 3 | 3つの特徴 | 時計表示 / 声のサポート / シーン別切り替え | 時計を大きく見せるブロックと、大小を変えた説明ブロック。ライト・夜の画面もここに配置 |
| 4 | キャラクター・声かけ体験 | 声かけサンプルの見出し・既存4キャラクター・4音声・無料/有料区分 | 大きなキャラクターとオフセット付き再生ボタンで、その場で試聴 |
| 5 | 活用シーン | 朝の支度 / 集中 / 遊びや片付けの切り替え | 一日の流れを感じる横並びの3場面。スマホは縦に読み進める |
| 6 | 無料版とTimeSense+ | ダウンロード説明・FAQのプラン情報 | 比較しやすい短い表。無料で始められる内容と追加機能を整理 |
| 7 | 開発者の想い | 「開発者より」の見出し・現在の家庭での経験と開発動機 | 現行文を手紙のような落ち着いた構図に配置 |
| 8 | よくある質問 | 現在の8問と回答・確認手順 | 「はじめる前に・購入」と「お困りのとき」の順で整理。回答は開閉式で全文を保持 |
| 9 | 最後のダウンロード | 現行見出し・両ストアのバッジ・無料で試せる案内 | 黄色の面にキャラクターが集合。既存案内をオフセット付きの面に配置 |
| 10 | フッター | 規約・プライバシー・運営・問い合わせ・特商法表記 | 濃紺の面に整理して配置 |

既存のセクション要素は、順序変更や統合で活用する。外部からのアンカー利用を考慮し、既存IDは引き継ぐか、対応先のアンカーを残す。

### ヒーローの具体案

第1節の固定文言をそのまま使用する。現行コピーの長さを前提にレイアウトを設計し、構図に合わせるための短縮はしない。

PCでは現行H1・サブコピーの幅を十分に取り、時計とキャラクターを横または下へ配置する。二列でコピーが窮屈になる場合は、上段にコピー、下段に大きな時計とキャラクターを置く。Lagoonの背景とオフセット面で世界観をつくる。Lumaを手前、Picoなどを周囲に配し、時計とキャラクターが一体になった構図にする。スマホは「ロゴ → 現行コピー → 時計とキャラクター → 操作」の順。狭い画面で全要素を無理に一画面に押し込まない。

主な操作は公式App Store / Google Playバッジ。補助操作は「声をきいてみる」で試聴セクションへ移動する。ストアバッジは公式の形を維持する。

### キャラクター試聴の具体案

- PCは4体を一望できる配置。スマホは2列を基本に、画像・名前・再生操作を十分な大きさで表示する。
- 各キャラクターに、名前、短い性格紹介、実際の音声に対応したセリフ、再生/停止操作を置く。
- 再生中だけ吹き出しやキャラクターが軽く反応する。別の音声を再生したら前の音声を停止する。
- 音声は利用者の操作で再生する。再生失敗時は状態を明示して再試行できるようにする。
- 無料/TimeSense+の表示は実際の公開版と照合する。現行LPはLuma/Picoを無料、Milo/Totoを有料としているが、そのまま最新仕様と断定しない。

### 機能・文章の整理

ルーティン、プロフィール、スタンプカードは現行FAQに存在する。公開版での仕様と見せる素材が確認できた場合に、特徴セクションに小さな補足として加える。新機能の開発はこのリニューアルの範囲に含めない。

文章変更はデザイン実装から分けて扱う。機能仕様と文章の不一致などに気づいた場合は修正候補として記録し、現行コピーを無断で差し替えない。第1節の固定文言はそのまま維持する。

## 6. 動きとスマホでの使いやすさ

- 最初の登場: キャラクターと時計が150〜400ms程度で軽く現れる。内容はすぐ読める状態にする。
- スクロール: 各セクションが初回だけ小さく現れる。通常の縦スクロールを維持する。
- タップ: 音声ボタンが押し込まれ、再生状態が文字でもわかる。
- 継続する装飾の動きは少数に限定し、停止操作を用意する。動きを減らす端末設定では静止表示にする。
- 現行のプリローダーと広範囲に動くパーティクルは、読み込み速度と主役の明確さを優先して整理する。
- スマホの操作領域は44px以上を目標にする。ホバーだけで現れる必須情報を作らない。
- 必要ならヒーロー通過後に小さな「ダウンロード」導線を下端に表示する。本文、FAQ、端末の安全領域と重ならないことを確認する。
- 文字拡大、キーボード、音声なしでも、主要な説明とストアへの移動が成立する構成にする。

## 8. 実装の進め方

### ステップ1: 内容と素材の確定

既存セクション・リンク・音声・FAQを一覧化し、最新公開版の画面とプラン仕様を照合。ロゴとキャラクターの品質を確認し、PC/スマホのワイヤーフレームを作る。

成果物: 現行コピー・見出し・検索向け情報の保存版、素材一覧、セクション別ワイヤーフレーム。

### ステップ2: 印象を決める3箇所のデザイン

ヒーロー、特徴、キャラクター試聴を先に具体化する。固定した現行コピーで、Lagoonを基準とした配色・明確なオフセット・Zen Maru Gothic・キャラクターの大きさを揃え、PCとスマホの両方で方向性を評価する。

成果物: 上記3箇所のデザインプレビューと基本スタイル。

### ステップ3: 日本語ページ全体の実装

ステップ2の表現を活用シーン、プラン案内、開発者メッセージ、FAQ、最後のダウンロードへ展開。音声再生、ナビ、FAQ開閉、動きを減らす設定に対応する。

成果物: 日本語LPのレビュー可能なプレビュー。

### ステップ4: 検証・調整

変更前後のH1・サブコピー・既存見出し・title・meta description・canonical・hreflangを比較し、意図しない文言変更や欠落がないことを確認する。表示上の改行変更と本文変更を区別する。

## 9. リポジトリ上の方針

- 現在の公開経路はAstroのビルドから`dist`をGitHub Pagesへ配置する構成。
- 公開元は`public/timesense/`。ルート直下にも`timesense/`があり、日本語HTMLの行数・内容が異なるため、実装対象を混同しない。
- 最初のリニューアルでは既存の静的HTMLの配信方式を活用し、共通CSS・JS・画像を分離する。日本語LPの完成を大規模な構成移行に依存させない。
- 多言語展開では共通スタイルと構造を使い、文章・音声・バッジなどを言語別に管理する。既存の文字列置換型生成スクリプトは、新HTMLへの対応と再生成結果の確認を行う。
- canonical / hreflang / title / description / 既存URLは維持し、OGP / sitemapと既存ストアURL・クエリパラメーターも欠落・意図しない変更がないか点検する。
- 試聴音声とダウンロード配信用の`voices/`、法務ページのリンクを維持する。
- 既存の計測を棚卸しし、プレビューでは本番イベントを送らない。公開後の比較に必要なイベントは使用中の計測基盤と合意した範囲で設計する。
- 既存作業中の変更や別製品のページを巻き込まない。生成先`dist`は実装の編集元にしない。

## 10. 完了の判断基準

- 最初の画面で、子ども向けの時計・声かけアプリであることと、TimeSenseのキャラクターが伝わる。
- 現行の「知育時計アプリ」・メインコピー・サブコピーの文言と、H1内の関係が維持されている。
- アプリ本体の配色とZen Maru Gothicに統一されている。
- Lagoonの前面・背面・ボタンの色の関係と、輪郭の明確な右下オフセットがページ全体の共通表現になっている。
- 時計の実画面とキャラクターが十分な大きさで見え、各セクションに明確な強弱がある。
- 既存の特徴・活用シーン・音声・開発の想い・FAQ・ストア導線・法務リンクが引き継がれている。
- 音声は再生中の状態が明確で、同時に重なって再生されない。
- スマホで横にはみ出さず、本文や主要操作を装飾・追従要素が覆わない。
- 既存言語と検索向け情報が維持され、画像・音声・リンク切れがない。
- 公開後は、取得可能な範囲でストアクリック率と試聴利用率を比較し、変化を評価する。インストール増加はLPだけでは断定しない。

優先順位は **現行コピー・検索向け情報の固定 → Lagoonとオフセットを軸にしたヒーローの刷新 → 配色・フォント・共通部品の統一 → 試聴の体験化 → 残りの構成整理 → 多言語・品質確認** とする。
